# V4.0: Smoke Detection & Notification System

This document outlines the purpose, architecture, and usage of the V4.0 video analytics pipeline. This version pivots from a general-purpose object counter to a specialized event-based monitoring system designed for detecting smoke emissions from industrial chimneys.

## 1. Use Case: Chimney Smoke Emission Monitoring

The primary goal of this system is to provide real-time, automated monitoring of a coke production line with multiple chimneys.

- **Input**: The system ingests live video streams from cameras pointed at the chimneys.
- **Detection**: It uses a custom-trained YOLOv8 model to detect 'smoke' in the video feeds.
- **Tracking**: Each smoke plume is tracked across consecutive frames to give it a unique identity. This is crucial to distinguish between a single, continuous emission event and multiple, separate events.
- **Alerting**: When a new smoke emission is detected within a predefined area (a chimney's Region of Interest), the system triggers an alert.
- **Notification**: The alert is dispatched as an email to a configured list of recipients. The email contains key information, such as the specific chimney number, the camera that saw it, and a timestamp.
- **Smart Filtering**: To prevent "alert fatigue," notifications are rate-limited. A notification is only sent for the *first* appearance of a specific track ID within a chimney's zone. A new alert for the same track will only be sent after a configurable cooldown period has passed, signifying a potential new event.

## 2. How It Works: Architecture Overview

The system retains its robust and efficient producer-consumer architecture, ensuring scalability and performance.

- **`main.py`**: The application's main entry point. It reads the configuration, selects the appropriate hardware profile (CPU or GPU), and orchestrates the startup and shutdown of all components. It also hosts an optional Flask-based health API.

- **`producer.py`**: The "Producer" is responsible for connecting to the camera streams defined in `config.yaml`. It runs a dedicated thread for each camera, handling connection retries and frame decoding. Processed frames, along with metadata like the camera ID, are placed into a shared, size-limited queue.

- **`consumer_gpu.py` / `consumer_cpu.py`**: The "Consumers" are the brains of the operation. They fetch frames from the producer's queue and perform the core analytics.
    - **`consumer_gpu.py` (Default/Recommended)**: Designed for maximum performance on CUDA-enabled GPUs. It collects a batch of frames and performs inference and tracking on the entire batch in a single, highly-optimized operation (`model.track()`).
    - **`consumer_cpu.py`**: A fallback for systems without a compatible GPU. It uses a thread pool to process frames from different cameras in parallel, maximizing CPU core utilization.

- **`NotificationHandler.py`**: This is the new logic center. It is a stateless module that receives tracking data from a consumer. It determines if a detected smoke track falls within a chimney's ROI and manages the notification cooldown logic to decide if an email alert should be sent.

- **`config.yaml`**: A centralized YAML file to configure every aspect of the system, from camera URLs and model paths to chimney locations and email server settings. This allows for easy modification without changing any code.

## 3. Core Logic Flow (GPU Example)

1.  **Frame Ingestion**: `producer.py` connects to the RTSP streams for `camera_1` and `camera_2`.
2.  **Queuing**: Frames are decoded, resized, and placed into a queue at the target FPS.
3.  **Batch Collection**: `consumer_gpu.py` pulls frames from the queue until its batch size is reached (`batch_size: 8`) or a timeout occurs.
4.  **Batched Inference**: The entire batch of 8 frames is sent to the GPU in a single `model.track()` call. The YOLOv8 model detects smoke and assigns a persistent track ID to each plume.
5.  **Result Processing**: The consumer loops through the results for each of the 8 frames.
    - For each frame, it extracts the list of active tracks (e.g., `[{track_id: 1, class: 'smoke', ...}]`).
6.  **Notification Check**: The list of tracks is passed to `notification_handler.check_and_notify()`.
    - The handler checks each track's location. If a smoke track's centroid is inside a chimney ROI defined in `config.yaml`:
    - It checks its internal log to see if a notification for that `chimney_id` and `track_id` has been sent recently.
    - If the `notification_cooldown` (e.g., 300 seconds) has passed, it logs the new event time and calls the `_send_email()` method.
7.  **Email Dispatch**: The `_send_email` method connects to the configured SMTP server and sends a formatted alert to all recipients.
8.  **Visualization (Optional)**: If `--visualize` or `--save` is enabled, the consumer renders the bounding boxes for the smoke, the track IDs, and the predefined chimney ROIs onto the frame before displaying it or saving it to a video file.

## 4. Configuration (`config.yaml`)

All operational parameters are controlled via `config.yaml`.

- **`model_name`**: The path to your trained smoke detection model (e.g., `yolov8n_smoke.pt`).
- **`classes_to_track`**: A list of class names the system should focus on. For this use case, it should be `["smoke"]`.
- **`notification_cooldown`**: The minimum time in seconds before sending a new alert for the same emission event.
- **`regions_of_interest`**: This critical section maps chimney IDs to their bounding box coordinates (`[x1, y1, x2, y2]`) on a per-camera basis. You must calibrate these values for your specific camera setup.
- **`email_notifications`**: Contains all settings required to send emails:
    - `enabled`: A master switch to turn notifications on or off.
    - `smtp_server`, `smtp_port`: Your email provider's server details.
    - `sender_email`, `password`: The login credentials for the email account that will send alerts. Using an "App Password" is highly recommended for services like Gmail.
    - `recipients`: A list of email addresses that will receive the alerts.

## 5. How to Run

The application is launched from the command line inside the `V4.0/` directory.

```bash
# To run using the GPU-optimized profile (recommended)
python main.py --profile gpu

# To run with real-time visualization windows
python main.py --profile gpu --visualize

# To run using the CPU-only profile and save the output as video files
python main.py --profile cpu --save

# To see all options
python main.py --help
```
